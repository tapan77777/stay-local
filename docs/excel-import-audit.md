# Excel import audit

Audited 2026-10-31 before implementation.

- Next.js 16.3.7 App Router, React 19, TypeScript, Tailwind; admin pages use shared PageHeader, Button and section cards. Relevant bundled Next route/action guides reviewed.
- Neon HTTP SQL (`lib/plan/db.ts`); five existing idempotent schema files, applied by `scripts/plan-migrate.mjs`. No ORM or validation library. Existing node smoke/device tests require a running app and configured database.
- `customers` → `plans` → ordered `destinations` → `itinerary_days`, `places`, `transports`, `stays`, `foods`, `experiences`, `map_pins`, `destination_notes`. Plan-level `india_guide_items` and `plan_documents`. Cascading content foreign keys; customer deletion restricted. Positions start at zero.
- Plan Overview: title, subtitle, traveler name, trip dates/days, style, budget style, profile photo, preferences, important notes. Help: WhatsApp contact, support information. Journey is destination ordering, not another table. Destinations include dates/nights, intro, hero and eight module image URLs. All module text/image/map/booking fields are supported. Prices, durations and recommended times are descriptive text, with no structured amount/currency/time schema.
- Authentication: signed HTTP-only admin cookie, shared `admin` identity; server-side requireAdmin. No individual admin accounts to attribute by name. Customer access uses private token, name session, access windows and devices. DRAFT is an editorial status, not an access gate. Never export tokens/access settings, device records, customer IDs or customer contact data. Select an existing customer in the admin UI for new imports.
- Builder writes directly through section services and server actions. Child edits do not touch plans.updated_at, so that timestamp cannot reliably detect stale workbooks. Add content-version triggers across content tables, serializing edits on their parent plan. Preserve status/access/token/customer fields on updates/restores.
- No revision mechanism exists. Add bounded, expiring server-side previews and immutable content snapshots for each Excel operation, including the baseline before first Excel update. Use Neon transactions with a locking version guard, atomic revision writes and one-use preview IDs.
- Workbook runtime needs a deployable server-side XLSX reader/writer (none installed). Use ExcelJS with ZIP preflight limits, formula/link rejection, strict sheet/header/type/enum/reference checks and human-readable cell locations. The spreadsheet skill's workstation artifact package is not an application runtime dependency here.
- Import/export schema uses one central allowlist shared by template generation, validation, preview and persistence. Stable keys resolve against only the selected plan; new IDs are generated server-side. Blank updates preserve values; `[CLEAR]` clears optional fields; `DELETE` explicitly removes rows. Parent deletion requires explicit child deletion. Missing rows are preserved. Preview supports selecting whole record changes, then revalidates resulting relationships.
- Migration is additive. Do not apply against the configured remote database automatically; verify using an isolated PostgreSQL test engine. No deploy or Git push.
